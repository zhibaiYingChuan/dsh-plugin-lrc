# dsh-plugin-lrc

把 [LRC](https://github.com/zhibaiYingChuan/LRC) 的长期记忆接进 DeepSeek Harness（DSH）：
**边聊边沉淀、按需召回、可纠错**，让上下文不再需要频繁压缩。

> 版本 **0.3.0** · [MIT License](LICENSE) · 适配 DSH `>=0.2.0-rc.1 <0.3.0-0`

> **安装状态说明（临时）**：`0.3.0` 已推送到 GitHub，但**尚未发布到 npm**。
> npm 上当前可安装的仍是旧版本，请勿从 npm 安装后期待 0.3.0 的功能。
> 想用 0.3.0 请走下面的「方式二：从 GitHub 安装」。

---

## 一句话说清它解决什么

DSH 的上下文会一直涨，涨到阈值就压缩，压缩就丢约束：

```
压缩前：40 轮对话，其中 3 条关键决策
压缩后："前面聊了包管理器。"        ← 决策没了
```

本插件不是"压缩时抢救"，而是**根本不让它涨到需要压缩**：把对话里的决策、约束、结论持续搬进 LRC 长期记忆库，上下文里只留一行状态快照。AI 需要细节时，再按需召回。

```
对话（线性、易失）
   ↓ 每 8 轮增量提炼
结构化记忆（决策 / 约束 / 结论 / 报错）
   ↓ 语义查重后写入
LRC 长期记忆库（持久、可检索）
   ↓ 回填一行状态快照
上下文（始终很小）
```

AI 看到的不再是几十轮原文，而是：

```
[LRC 状态] 已确定用 pnpm（放弃 npm 因兼容问题）；端口纪律 3099/3111。
           细节在 LRC，需要时 recall。
```

## 它能给你带来什么

| 能力 | 你感知到的效果 |
|---|---|
| **自动沉淀** | 每轮对话的决策 / 约束 / 结论自动存进本地记忆库 |
| **按需召回** | 新会话里 AI 能想起"上次为什么这么定""你偏好用什么" |
| **主动注入**（0.3.0） | 话题切换时自动把相关记忆推进上下文，不用等 AI 想起来查 |
| **主动纠错** | AI 发现记错了，能主动撤回，不让错误结论污染后续 |
| **会话交接** | 上下文快满时，整理成交接摘要，另起会话继续 |
| **长文本落盘**（0.3.0） | 几百页文档 / 上万行代码落盘为工件，上下文只留一行指针，按需分段取回 |
| **状态自检** | 随时查插件是否正常、哪些能力可用 |
| **上下文裁剪** | 自动裁剪旧历史，让长对话不中断 |

### 0.3.0 新增的能力细节

| 能力 | 说明 |
|---|---|
| **结构化记忆** | 记忆不再只是自由文本，而是 `(类别, 主体, 关系, 取值)` 三元组 + 自足陈述，可用于冲突判定与去重 |
| **LLM 兜底判定** | 规则抽不到时，用一次独立模型调用判断"这句值不值得记"。这是唯一产生额外计费的路径，默认关闭，需显式开启 |
| **双闸门召回** | 注入前过两道：相对分 ≥0.85（同批里不算掉队）+ RRF 绝对分 ≥0.025（至少两路检索命中）|
| **注入自带时效声明** | 注入段落标注「可能过时，与当前任务无关时请忽略」，判断权留给模型 |

## 安装

### 前置条件

- DSH `>= 0.2.0-rc.1`
- Node.js `>= 20`

### 方式一：从 npm 安装（**0.3.0 暂不可用**）

> 0.3.0 尚未发布到 npm。下面的命令目前只能装到旧版本，功能与本文描述不符。
> 等 0.3.0 发布后此方式才可用。

```bash
dsh plugin --profile desktop add dsh-plugin-lrc
```

### 方式二：从 GitHub 安装（**当前推荐**）

```bash
# 把 desktop 换成你的 profile 名（web / desktop / ...）
dsh plugin --profile desktop add github:zhibaiYingChuan/dsh-plugin-lrc
```

确认它真的进了插件树：

```bash
dsh --profile desktop --dump-config | grep dsh-plugin-lrc
```

### 安装 LRC 本体

插件负责**调用** LRC，但需要有 LRC 可调。两种方式二选一：

**A. 已装 LRC 就直接用**（推荐）

插件启动时先探测本地实例（`baseUrl` 配置 → `LRC_BASE` 环境变量 → `127.0.0.1:3099`），
探到就复用，不另起进程，也不碰它的数据。

- 国内下载（推荐）：<https://sfang.cc/longyi>
- GitHub Releases：<https://github.com/zhibaiYingChuan/LRC/releases>

**B. 没装就让插件自己拉**

插件会按平台下载 LRC 二进制，**不需要你指定版本**：

1. 向 GitHub 的 `releases/latest/download/` 取当前版本的 `.sha256`
   （国内镜像只用来加速下载，不代表版本——镜像同步会滞后，不能让它决定你装哪一版）
2. 与本地缓存比对：一致则直接复用，不一致（LRC 发了新版）则自动重下
3. 下载后校验 SHA256，通过才启动；镜像内容与官方指纹不符会被判为"镜像落后"并自动跳过
4. 校验失败一律删除并报错，**绝不运行未校验的二进制**

缓存位置 `$DSH_HOME/cache/lrc-plugin/bin`，与你的桌面端 LRC 数据目录互不影响。

> 下载源只用稳定路径（`/xd/downloads/`、GitHub `releases/latest/download/`），
> 版本号不写进插件代码——LRC 发新版时插件无需升级。
> 一小时内的重复启动会复用上次的检查结果，不会每次都去连境外；
> 离线且本地已有缓存时，直接沿用本地版本继续工作。

**C. 都没有**

降级为纯客户端模式：插件加载不报错，但沉淀会静默跳过。`lrc_status` 会显示原因与重试倒计时。

**连接是自动恢复的，不需要重启**

LRC 比编辑器晚启动是常态（实测桌面端晚 20 分钟）。插件的连接不是"启动时决定一次"，而是：

| 情形 | 行为 |
|---|---|
| LRC 暂时不在 | 记一次失败原因，按 2s → 4s → 8s…（封顶 60s）退避重试 |
| LRC 后来起来了 | **下一次工具调用自动连上**，无需重启插件或重新加载 |
| 用着用着断了 | 热路径识别为连接错误，立刻作废连接，下次调用重连 |
| 参数类错误（400/422） | 不动连接——服务是活的，掐掉反而误伤 |

未连接期间对话内容**不会丢**：新增内容仍计入待沉淀队列，连上后自动补写。

**数据到底写在哪，取决于模式**：

| 模式 | 数据目录 | 说明 |
|---|---|---|
| `external`（复用已有实例） | 那个实例自己的目录，例如 `~/.loong-recall/global/data` | 插件**不拥有**这份数据，删 `~/.dsh/cache/lrc-plugin/data` 清不掉它 |
| `managed`（插件自启） | `$DSH_HOME/cache/lrc-plugin/data` | 只有这个目录是插件自己的 |
| `degraded`（降级） | 不写 | 只做上下文裁剪，不沉淀 |

清理测试数据前先看日志里的 `复用已有实例` / `已启动隔离实例`，别删错。

## 使用

安装后无需额外操作，插件会自动工作。你也可以让 AI 主动调用这些工具：

| 工具 | 用途 |
|---|---|
| `lrc_recall` | 召回相关记忆（涉及项目历史、用户偏好、之前决策时先调它） |
| `lrc_forget` | 删除一条错误记忆（id 从 `lrc_recall` 输出里取） |
| `lrc_remember_now` | 立即把当前对话沉淀到记忆库 |
| `lrc_handoff` | 整理交接摘要并新建会话 |
| `lrc_fetch_artifact` | 按 hash 取回落盘的长文本，支持 `offset` 分段读（0.3.0）|
| `lrc_status` | 查看插件运行状态（能力矩阵、熔断、阈值、上下文画像） |

> DSH 没有 MCP 客户端，AI 看不到 LRC 原生的 MCP 工具。所以插件把读 / 写 / 纠错都注册成了**原生工具**，AI 直接就能用。

## 配置

在 `cordis.patch.yml` 的 `config:` 下配置（或通过 DSH 配置界面）：

| 配置项 | 缺省 | 说明 |
|---|---|---|
| `baseUrl` | 空 | 指向已有 LRC 实例；留空则自动探测 / 启动 |
| `token` | 空 | 服务端设了 `LRC_API_TOKEN` 时必填 |
| `project` | `dsh` | 记忆归属项目 |
| `offloadTurns` | `4` | 每多少轮沉淀一次 |
| `offloadChars` | `6000` | 累计多少字符沉淀一次 |
| `offloadSteps` | `8` | 累计多少步沉淀一次（长任务里正文很少，靠步数兜底） |
| `maxItems` | `40` | 单次最多提炼条数 |
| `contextWindowTokens` | `0` | 显式指定模型窗口；`0` = 自动探测 |
| `trimRatio` | `0.1` | 裁剪阈值占窗口比例（1M 窗口 → 100K）|
| `trimMinTokens` | `30000` | 窗口未知时的裁剪阈值（绝对值） |
| `trimMinSteps` | `10` | 两次裁剪之间至少间隔多少步 |
| `trimMaxNodes` | `120` | 节点数硬上限：不依赖 token 计量，计量失真时兜底 |
| `trimMaxSummaryChars` | `4000` | 单次摘要字符上限 |
| `pruneResultThreshold` | `4096` | 工具输出超过多少字符才剪枝 |

### 0.3.0 新增配置

| 配置项 | 缺省 | 说明 |
|---|---|---|
| `recallInjectEnabled` | `false` | 是否主动把相关记忆注入上下文 |
| `recallInjectMaxItems` | `2` | 单次最多注入几条 |
| `recallInjectMinScore` | `0.85` | 相对分下限（同批内不算掉队）|
| `recallInjectMinRawScore` | `0.025` | RRF 绝对分下限（约等于「至少两路检索命中」）|
| `recallInjectMaxCharsPerItem` | `80` | 单条截断字符数 |
| `llmExtractEnabled` | `false` | 是否启用 LLM 兜底判定（**唯一计费路径**）|
| `llmExtractMaxCalls` | `200` | 会话级调用上限 |
| `llmExtractGlobalMaxCalls` | `500` | 进程级上限（滑动窗口 1 小时）|
| `llmExtractMinIntervalMs` | `5000` | 两次调用最小间隔 |
| `llmExtractMinChars` | `120` | 正文短于此长度不触发 |
| `artifactEnabled` | `true` | 是否启用长文本落盘 |
| `artifactMinChars` | `8000` | 超过多少字符才落盘 |
| `artifactQuotaMb` | `200` | 工件库磁盘配额（MB），超额按最久未访问淘汰 |

## 工作原理：分区准入，代码只判形态

筛选分两层，**价值判断交给 LLM，代码只做可计算的形态判断**。

| 层 | 做什么 |
|---|---|
| 1. 规则路径 | 拆得出 `(类别, 主体, 关系, 取值)` 三元组的句子，零成本直接入库 |
| 2. LLM 路径 | 拆不出三元组的句子进 `pending` 队列，由模型判定「值不值得记」；判定通过后只留形态底线（长度 / markdown 碎片 / 机器输出 / 提问）|
| 3. 本地查重 | Jaccard ≥ 0.85 视为复述，连 HTTP 都不发 |

> 为什么不让代码做价值判断：实测 82 条候选句，结构判据**全部通过（零区分力）**；
> 换成 95 词谓词白名单后只剩 **3 条（96% 误杀）**。“这句话值不值得记”是语义问题，
> 用封闭词表近似开放语言必然漏。

触发沉淀的条件（任一）：累计 8 步 / 4 轮正文 / 6000 字符，外加 **turn 结束时无条件兜底**。

## 实测数据

### 压缩效果（2026-11，真实 DSH 会话 session-95eaf7e3）

条件：单次会话连续运行约 **17 小时 / 536 步 / 5,150 次工具调用**，窗口 1,000,000 tokens。

- **上下文水位稳定在 6.8%–7.9%**（56,612 – 79,117 tokens），全程未接近 10% 红线。
- **压缩 30 次，全部由节点数 120 触发**，token 阈值（100K）一次都没有触发。
- 累计压缩掉 **1,072,703 tokens**，摘要开销约 12 万字符。
- **完全不压缩时上下文峰值会到 1,198,394 tokens**，超出 1M 窗口 —— 会话会在中途直接失败。
- 缓存命中率 94.0%；单会话实际支出约 ¥36（按 DeepSeek 官方价估算）。

### 信息提炼与召回

- 记忆写入 **548 条**（LLM 兜底判定层 135 次调用），正文规则抽取另写 44 条。
- 召回双闸门两次实测：**5 条候选放行 1 条**、**6 条候选放行 2 条**，无“全放”或“全拦”。
- 长任务中**无漂移、无幻觉**。发生的一次内容偏差经溯源确认**不是插件原因**：
  用户选定的图标编号在压缩前后连续 12 次摘要中全部保留，模型执行时它们就在上下文里，
  是模型未把“用户已确认”当成硬约束。

> 一句话：压缩保证**信息不丢**，但不能保证**模型遵守信息**。后者属于模型的指令遵循问题。

## 诚实说明

- 上下文仍会增长（用户消息、工具输出）。插件做的是把**结论性内容**持续搬走，并用确定性摘要置换早期历史，让水位稳定在安全区（实测 6.8%–7.9%）。
- **不承诺"永不压缩"**，承诺"压缩后关键信息不丢、长任务不中断"。
- **不承诺模型一定遵守记忆**。插件保证信息进入上下文，但"用户已确认的事不被改掉"属于模型的指令遵循能力，不在插件责任范围内。
- 规则层提取在复杂任务上命中率低（实测 69 次沉淀仅写入 9 条），大部分产出依赖 LLM 兜底判定。后者默认关闭、需显式开启，且受会话/进程双层配额约束。
- 模型窗口探测：宿主对未知模型可能返回 `1,000,000` 哨兵值，插件会保守降级到 `trimMinTokens=30000`。若确知模型窗口，请显式配置 `contextWindowTokens`。
