# dsh-plugin-lrc

把 [LRC](https://github.com/zhibaiYingChuan/LRC) 的长期记忆接进 DeepSeek Harness（DSH）。

一句话：**边聊边把结论存进本地记忆库，上下文不用一直涨；需要细节时再按需取回。**

> 版本 **0.3.1** · [MIT License](LICENSE) · 适配 DSH `>=0.2.0-rc.1 <0.3.0-0`

> **npm 上只有 0.2.1**。0.3.x 还没发布到 npm，请从 GitHub 安装（见下文）。

---

## 它解决什么问题

DSH 的上下文会一直涨。涨到阈值就压缩，压缩容易把约束和决策弄丢：

```
压缩前：40 轮对话，其中 3 条关键决策
压缩后："前面聊了包管理器。"        ← 决策没了
```

这个插件不是等压缩时抢救，而是**把结论持续搬走**：对话里的决策、约束、结论写进 LRC，
上下文里只留一行状态。AI 需要细节时，再调工具取回来。

```
对话（线性、易失）
   ↓ 每 4 轮 / 6000 字符 / 8 步，增量提炼
结构化记忆（决策 / 约束 / 结论 / 报错）
   ↓ 同批折叠 + 语义查重
LRC 长期记忆库（持久、可检索）
   ↓ 回填一行状态快照
上下文（始终很小）
```

## 安装

```bash
# 把 desktop 换成你的 profile 名（web / desktop / ...）
dsh plugin --profile desktop add github:zhibaiYingChuan/dsh-plugin-lrc

# 确认真的进了插件树（这步不能省）
dsh --profile desktop --dump-config | grep dsh-plugin-lrc
```

第 2 步没输出 = 没装上。最常见原因是包被当成普通 npm 依赖装了，但没进插件树。

### LRC 从哪来

插件启动时按顺序找：

1. 配置里的 `baseUrl`
2. 环境变量 `LRC_BASE`
3. `127.0.0.1:3099`

找到就复用，不另起进程，也不碰它的数据。

找不到就自己下载一个隔离实例，数据放在 `$DSH_HOME/cache/lrc-plugin/data`，
和你的桌面端 LRC 数据目录互不影响。下载会校验 SHA256，校验不过一律删除报错。

都没有就降级：插件正常加载，但沉淀静默跳过，对话照常。`lrc_status` 会显示原因。

### 连接是自动恢复的

LRC 比编辑器晚启动很常见。插件不是"启动时决定一次"：

| 情形 | 行为 |
|---|---|
| LRC 暂时不在 | 按 2s → 4s → 8s…（封顶 60s）退避重试 |
| LRC 后来起来了 | 下一次工具调用自动连上，不用重启 |
| 用着用着断了 | 识别为连接错误，作废连接，下次重连 |
| 参数错误（400/422） | 不动连接——服务是活的 |

未连接期间对话内容不会丢：仍计入待沉淀队列，连上后补写。

## 它会做什么

| 能力 | 说明 |
|---|---|
| **自动沉淀** | 每 4 轮 / 6000 字符 / 8 步，把决策、约束、结论写进 LRC |
| **同批折叠** | 一次 flush 的 N 条碎片先压成 1 条摘要再入库，避免记忆库被短句淹没 |
| **会话纪要** | 一段对话产出一份纪要：诉求演进 + 关键结论 + 真实时序 |
| **按需召回** | AI 调 `lrc_recall` 取回相关记忆；历史类问题会先取纪要再取细节 |
| **主动注入** | 话题切换时把相关记忆推进上下文（默认关闭，需显式开启） |
| **主动纠错** | AI 发现记错了，用 `lrc_forget` 撤回 |
| **会话交接** | 上下文快满时整理成交接摘要，另起会话继续 |
| **长文本落盘** | 整份文档 / 超长代码落盘为工件，上下文只留一行指针，按需分段取回 |
| **上下文裁剪** | 自动裁剪旧历史，让长对话不中断 |
| **状态自检** | `lrc_status` 查看能力矩阵、连接状态、阈值 |

## 工具

DSH 没有 MCP 客户端，所以插件把读写都注册成了原生工具：

| 工具 | 用途 |
|---|---|
| `lrc_recall` | 召回相关记忆。涉及项目历史、用户偏好、之前决策时先调它 |
| `lrc_forget` | 删除一条错误记忆（id 从 `lrc_recall` 输出里取） |
| `lrc_remember_now` | 立即把当前对话沉淀到记忆库 |
| `lrc_handoff` | 整理交接摘要并新建会话 |
| `lrc_fetch_artifact` | 按 hash 取回落盘的长文本，支持 `offset` 分段读 |
| `lrc_status` | 查看插件运行状态 |

## 配置

在 `cordis.patch.yml` 的 `config:` 下配置。**参数必须写在 `config:` 下面**，
写在 entry 顶层会被静默忽略。

### 基础

| 配置项 | 缺省 | 说明 |
|---|---|---|
| `baseUrl` | 空 | 指向已有 LRC；留空则自动探测 / 启动 |
| `token` | 空 | 服务端设了 `LRC_API_TOKEN` 时必填 |
| `project` | `dsh` | 记忆归属项目 |
| `offloadTurns` | `4` | 每多少轮沉淀一次 |
| `offloadChars` | `6000` | 累计多少字符沉淀一次 |
| `offloadSteps` | `8` | 累计多少步沉淀一次（长任务里正文少，靠步数兜底） |
| `maxItems` | `40` | 单次最多提炼条数 |

### 折叠与纪要

| 配置项 | 缺省 | 说明 |
|---|---|---|
| `foldEnabled` | `true` | 同批折叠开关 |
| `foldMinFacts` | `4` | 低于几条不折叠 |
| `foldMaxChars` | `2000` | 折叠摘要字符上限 |
| `minutesEnabled` | `true` | 会话纪要开关 |
| `minutesEveryTurns` | `5` | 每满多少轮写一次纪要 |
| `minutesIdleMs` | `600000` | 空闲多久强制落一次（0 = 关闭） |
| `minutesStageMs` | `600000` | 一轮未结束时的阶段写入间隔（0 = 关闭） |

### 召回注入

| 配置项 | 缺省 | 说明 |
|---|---|---|
| `recallInjectEnabled` | `false` | 是否主动注入相关记忆 |
| `recallInjectMaxItems` | `2` | 单次最多注入几条 |
| `recallInjectMinScore` | `0.85` | 相对分下限（同批内不算掉队） |
| `recallInjectMinRawScore` | `0.025` | RRF 绝对分下限（约等于「至少两路检索命中」） |
| `recallInjectMaxCharsPerItem` | `80` | 单条截断字符数 |
| `recallInjectFragmentPrefixes` | `^(?:改成\|改用\|换成\|改为\|换掉\|删掉\|去掉\|只保留)` | 无主语残句前缀判据（空串 = 关闭） |
| `recallInjectFragmentExemptImportance` | `9` | 重要性达到此值不受前缀判据限制 |

### LLM 兜底判定

| 配置项 | 缺省 | 说明 |
|---|---|---|
| `llmExtractEnabled` | `false` | 是否启用（**唯一会产生额外模型调用的路径**） |
| `llmExtractMaxCalls` | `200` | 会话级调用上限 |
| `llmExtractGlobalMaxCalls` | `500` | 进程级上限（滑动窗口 1 小时） |
| `llmExtractMinIntervalMs` | `5000` | 两次调用最小间隔 |
| `llmExtractMinChars` | `120` | 正文短于此长度不触发 |
| `llmExtractMaxInputChars` | `6000` | 单次发送正文上限（超出取尾部） |

### 工件库与裁剪

| 配置项 | 缺省 | 说明 |
|---|---|---|
| `artifactEnabled` | `true` | 长文本落盘开关 |
| `artifactMinChars` | `8000` | 超过多少字符才落盘 |
| `artifactQuotaMb` | `200` | 工件库磁盘配额（MB），超额按最久未访问淘汰 |
| `trimEnabled` | `true` | 上下文裁剪开关 |
| `contextWindowTokens` | `0` | 显式指定模型窗口；`0` = 自动探测 |
| `trimRatio` | `0.1` | 裁剪阈值占窗口比例 |
| `trimMinTokens` | `30000` | 窗口未知时的裁剪阈值 |
| `trimMinSteps` | `10` | 两次裁剪最小间隔步数 |
| `trimMaxNodes` | `120` | 节点数硬上限（不依赖 token 计量） |
| `trimMaxSummaryChars` | `4000` | 单次摘要字符上限 |

## 工作原理

### 沉淀：代码只判形态，价值判断交给模型

| 层 | 做什么 |
|---|---|
| 1. 规则路径 | 拆得出 `(类别, 主体, 关系, 取值)` 的句子，零成本直接入库 |
| 2. LLM 路径 | 拆不出的句子进 `pending`，由模型判定「值不值得记」；通过后只留形态底线 |
| 3. 本地查重 | Jaccard ≥ 0.85 视为复述，连 HTTP 都不发 |

为什么不让代码做价值判断：实测结构判据对「垃圾」和「真判断句」几乎没有区分力，
换成谓词白名单又会大量误杀。「这句话值不值得记」是语义问题，封闭词表近似不了开放语言。

### 召回：历史问题先取纪要

记忆库里有三种东西：会话纪要（叙事）、折叠批次（细节）、原始碎片（单句）。

历史类问题（「上次那个方案是什么」）会先按 `session-minutes` 标签取 1 条纪要，
再取明细，按 id 去重后纪要排最前。明细类问题（「图标尺寸是多少」）直接查全库，
不浪费纪要的几千字符。

### 注入：双闸门 + 软提示

注入前过两道：相对分 ≥ 0.85（同批里不算掉队）+ RRF 绝对分 ≥ 0.025（至少两路命中）。
注入段落标注「可能过时，与当前任务无关时请忽略」，判断权留给模型。

## 已知限制

- **上下文仍会增长**（用户消息、工具输出）。插件做的是把结论搬走、用摘要置换早期历史，
  让水位稳定在安全区，不承诺「永不压缩」。
- **不承诺模型一定遵守记忆**。插件保证信息进入上下文，但「用户已确认的事不被改掉」
  属于模型的指令遵循能力。
- **规则层提取命中率有限**，复杂任务上大部分产出依赖 LLM 兜底判定。后者默认关闭、
  需显式开启，且受会话 / 进程双层配额约束。
- **历史查询靠关键词判断**。中文里「回顾之前的方案」（历史）和「回顾之前的改动」（当前）
  字面同形，正则无法区分。当前策略是宁可漏触发，其余交给模型主动调 `lrc_recall`。
- **模型窗口探测**：宿主对未知模型可能返回哨兵值，插件会保守降级到 `trimMinTokens`。
  确知窗口时请显式配置 `contextWindowTokens`。
